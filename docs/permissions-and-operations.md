# 权限模型与可执行操作

## 先理解两层权限

1. **LuCI 管理权限**由登录的路由器管理员操作。客户端令牌不能打开管理 API、给自己授权、批准申请或确认恢复。
2. **MCP 客户端权限**由 LuCI 为每个客户端单独配置。新建客户端没有查询组和普通操作授权。仅知道 MCP 地址或拿到另一客户端令牌，不会获得这台客户端的权限。

MCP 服务仅监听 `127.0.0.1:8730`；推荐的远程访问方式是 SSH 本地转发。此权限边界不限制 root SSH 用户。

## 查询权限组

| LuCI 权限组 | 允许读取的范围 |
| --- | --- |
| `system` | `system.board`、`system.info` |
| `network` | 指定网络接口和设备状态；包括接口 dump/status、device status 和 `luci-rpc.getNetworkDevices` |
| `devices` | 主机提示、DHCP 租约、无线设备以及 iwinfo 无线信息 |
| `logs` | 系统日志 `logread`，返回内容会过滤敏感行 |
| 发现 | `ubus_list` 只列出对象、方法和参数签名；只用于能力发现，不读取配置 |

查询组只开放上述固定方法映射，不等于允许调用任意 ubus 写方法。新客户端的四组查询默认关闭。发现工具始终可用。

### 从旧策略迁移

旧版 `/etc/config/openwrt-mcp` 策略仍需同时满足 LuCI 查询组和旧策略本身的工具范围、scope、启用状态、到期时间及 MFA 要求。LuCI 显示“继承旧策略”时，按旧规则执行；旧策略过期或 scope 不覆盖目标方法时继续拒绝。

管理员可以在 LuCI 显式开放或关闭一个查询组。显式设置后，该组按 LuCI 权限配置授权；确认迁移后再按计划清理旧配置。不要为了排障给客户端设置 `*` scope 或通用 `exec` 权限。

## 普通操作：限时授权

普通操作仅包括：

- 在现有可选 OpenClash 策略组中切换到已有节点。
- 切换已支持的代理模式：`rule`、`global`、`direct`。

管理员在 LuCI 按客户端授予 `node` 或 `mode` 临时权限，持续时间为 1 至 60 分钟；界面默认 15 分钟。grant 只覆盖对应操作类别，不能延长自身有效期。未授权、过期、暂停操作或参数不在现有节点/策略组中时，服务拒绝执行。

直接切换只允许已经取得相应有效授权的普通操作。也可以通过 `request_operation` 提交申请，再由 LuCI 管理员逐笔批准。

## 敏感操作：逐笔批准

下列操作没有长期 grant：

| 操作 | 支持的参数 | 恢复方式 |
| --- | --- | --- |
| OpenClash 服务重启 | 无 | 不可回滚；可能中断现有连接 |
| 配置修改 `config_set` | 经固定 allowlist 验证的 `key,value` | 由恢复服务暂存旧值；需在 120 秒窗口内由管理员确认保留，否则恢复 |
| 静态 DHCP 租约 `dhcp_lease` | `section,ip,mac,hostname` | 由恢复服务暂存旧租约；需人工确认保留，否则恢复 |

配置写入仅允许以下字段：

- `network.lan.ipaddr`、`network.lan.netmask`
- `network.wan.dns`、`network.wan.peerdns`
- `uhttpd.main.listen_http`、`uhttpd.main.listen_https`
- 已存在且为 LAN 到路由器本机的防火墙管理规则中的 `src_ip`、`dest_port`、`target`、`enabled`

代码还会校验地址格式、端口、LAN 来源与防火墙规则类型。防火墙规则不得指向另一目标区域；并非所有同名 UCI 字段都能修改。

静态租约必须使用 `mcp_` 前缀的 section 名。IP 必须为有效 IPv4，MAC 必须为 6 字节地址，hostname 只接受字母、数字和连字符。服务不会接受任意 UCI 配置名或任意 section 写入。

## 一次申请如何流转

1. 客户端调用 `request_operation`。它只提交申请，不执行，也不能更改权限。
2. 申请有效期为 5 分钟。LuCI 显示请求摘要、变更前后值及敏感性提示。
3. 管理员逐笔查看具体预览并在 LuCI 批准。批准绑定预览摘要；执行前服务会重读当前状态，内容变化则取消申请并要求重新提交。
4. 可恢复的配置/租约修改进入最多 120 秒的等待确认窗口。管理员须从新的管理连接确认路由器仍可访问，才能保留修改。
5. 过期、恢复服务发现连接故障，或路由器进程在确认前中断时，恢复服务按记录恢复目标值。它会检查是否有别的更新覆盖了目标值；遇到新值冲突时拒绝覆盖。

MCP 客户端只能读取自己提交的申请状态。它不能批准、拒绝、确认保留或调用管理员回滚接口。LuCI 才能执行这些管理操作。

## 全局暂停、服务重启和审计

- LuCI 全局暂停会清除临时操作 grant 与待处理申请，并停止接受 MCP 写操作；查询权限保留。
- MCP 服务重启会清除内存中的临时授权、取消尚未执行的请求，并确保未确认的可恢复修改继续回滚。
- 恢复守护进程由独立 procd 服务监视，不依赖 MCP 服务仍在运行。
- 审计保留操作类型、客户端和结果摘要；令牌不会写入审计。系统日志读取会过滤带有 password、secret、token、subscription 等关键字的敏感行。

## 明确不开放的能力

在 LuCI 管理模式下，普通 MCP 工具不能用于通用 shell、任意 UCI 写入、访问 OpenClash dashboard secret 或自行扩大授权。遗留的 `exec`、`uci_apply`、`uci_confirm`、`wg_new_client` 等工具即使出现在某个旧 MCP 客户端缓存中，也不会因此得到本管理模式的授权。必要时在客户端工具过滤器中只启用 [客户端接入文档](client-setup.md)列出的工具。
